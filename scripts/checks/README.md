# Page checks (Good Neighbors Wildlife)

Run against a local production build: `npm run build && npx next start -p 3000`.

When done, stop the server with `pkill -f "next[-]server"`. The process renames itself to `next-server`, so killing the job's PID leaves it running, the next `next start` fails with EADDRINUSE, and the next crawl silently reads the old build.

- `node scripts/checks/crawl.mjs <outDir>` — crawls every sitemap page (plus the pages in `EXTRA_PATHS`, kept out of the sitemap on purpose, such as /november-special, the one page allowed a price, $699 only): 200s, unique titles/H1s/descriptions, FAQPage schema matching the rendered questions, tel: links, banned words, exact guarantee wording, word counts. Saves each page's HTML into `<outDir>` and prints problems.
- `node scripts/checks/compare.mjs <beforeDir> <afterDir>` — diffs two crawls page by page, ignoring build hashes, so a change can be shown to touch only the pages it meant to.
- `node scripts/checks/wording.mjs <crawlDir> <page.html>...` — renders a crawled page's content as markdown, for the owner to read every word.
- `node scripts/checks/shots.mjs <outDir>` — full-page screenshots at desktop and phone widths. Needs `playwright-core` (install it outside the repo, e.g. `npm i --no-save playwright-core`, or in a scratch folder) and a Chromium at `/opt/pw-browsers/chromium`; adjust `executablePath` otherwise.
- `node scripts/checks/firstscreen.mjs <outDir>` — phone first screen (375 x 812) of the 33 ad landing pages: the H1, the guarantee line and the page's own Call button must sit above the fixed Call Now bar (the pages in `NO_GUARANTEE`, which carry no guarantee line by the owner's choice, need only the H1 and the Call button); saves a screenshot per page and exits 1 on a failure (`/contact` is reported, not failed, by design). Needs `playwright-core` like shots.mjs.
- `node scripts/checks/lighthouse.mjs <runs> <path>...` — local Lighthouse, mobile, simulated slow 4G and 4x CPU, median of N runs (score, FCP, LCP, TBT, CLS). Needs `lighthouse` and `chrome-launcher` installed outside the repo (for example `npm i lighthouse chrome-launcher` in a scratch folder, with a copy of the script beside it) and `CHROME_PATH` if Chromium is not at `/opt/pw-browsers/chromium`. The ads chat's target is LCP under 2.5 s on PageSpeed Insights mobile. These local runs load no Google tags (a cloud session cannot reach googletagmanager.com), so the live site's blocking time will be higher; compare before and after on the same machine rather than against PageSpeed Insights.
- `node scripts/checks/gtagtiming.mjs` — Google tag timing and queueing, with a stand-in for gtag.js (a cloud session cannot reach Google): the library starts after the load event on the pages in `GOOGLE_TAG_LAZY_PATHS` and before it elsewhere, and a phone tap (including the Ads phone-tap conversion) made before the library arrives is queued and still there when it loads. Exits 1 on a failure. Needs `playwright-core`. It cannot prove Google records the events; that is tested in Google Ads and GA4 after go-live.

Run everything from the repo root; put output folders outside the repo or in a gitignored place.
